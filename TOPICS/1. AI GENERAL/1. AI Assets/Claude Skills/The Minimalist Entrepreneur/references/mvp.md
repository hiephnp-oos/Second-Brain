# MVP

## Purpose

Define and deliver a minimum viable product with minimal scope, starting from manual execution to validated automation.

---

## When to Apply

- Idea has been validated
- Need to build first version of product
- Struggling with scope or overbuilding
- Ready to deliver value to first customers

---

## Core Principle

Build the **smallest possible solution** that delivers value.

Focus on:
- speed over completeness
- function over polish
- delivery over perfection

---

## Workflow

### Stage 1 — Manual

- Solve the problem manually for each customer
- Execute all steps yourself
- Document the exact workflow

Goal:
- Prove value delivery works in reality
- Understand actual operations

---

### Stage 2 — Processized

- Convert manual steps into a repeatable system
- Document so another person can execute it
- Optimize for consistency and efficiency

Goal:
- Reduce reliance on individual execution
- Create a transferable workflow

---

### Stage 3 — Productized

- Automate validated steps only
- Build software or tools based on proven workflow
- Remove manual bottlenecks gradually

Goal:
- Scale delivery without losing value

---

## Build Constraints

Before building, validate:

- Can this be delivered within 2–3 days?
- Does it improve the user’s situation measurably?
- Will users pay for it now?
- Can feedback be collected immediately?

If any answer is “no” → reduce scope

---

## What to Build

- One core function only
- Minimal interface (forms, lists, basic CRUD)
- Use existing tools (no-code / low-code where possible)
- Charge from the beginning

---

## What NOT to Build

- Future features or assumptions
- Scalability infrastructure
- Mobile app if web is sufficient
- Custom code when simpler tools exist
- Team before necessity

---

## Execution Guidelines

- Ship early and iterate continuously
- Expect initial version to be wrong
- Improve based on real usage, not assumptions
- Prioritize feedback loops over feature expansion

---

## Essentials Checklist

Before launch:

- [ ] Business name defined (clear, simple)
- [ ] Domain acquired
- [ ] Basic website/live page created
- [ ] Payment system set up
- [ ] Communication channel ready (email or equivalent)
- [ ] Initial distribution channel identified

---

## Output

Define clearly:

1. Core function of MVP (single use-case)
2. Simplest implementation method (manual / no-code / minimal code)
3. Deliverable within 2–3 days
4. Initial pricing
5. Feedback collection method
