# Synthesis

Cross-framework knowledge that emerges only when multiple thinking libraries are used together.

## Boundary
Synthesis is not a second framework library. It does not redefine concepts already owned by a physical library.

Use this layer only for:
- recurring combinations of two or more frameworks;
- integrative decision patterns;
- cross-framework trade-offs;
- meta-models that improve framework selection or sequencing.

## Contract
Each synthesis artifact should identify the problem pattern, contributing frameworks, integration logic, each framework's contribution, limitations, and when the combined pattern is useful.

If a statement can live entirely inside one framework, keep it there.

## Artifacts
- CROSS-FRAMEWORK.md — stable combinations across the eight libraries.
- DECISION_PATTERNS.md — reusable decision sequences.
- STRATEGIC_PATTERNS.md — strategy patterns combining interaction, systems, evidence, and decision quality.
- META-MODELS.md — higher-order rules for selecting and sequencing frameworks.

## Promotion rule
Promote a synthesis pattern only when it is supported by at least two framework owners, materially more useful than either framework alone, and reusable beyond one isolated situation.

No personal experience is treated as synthesis merely because it mentions multiple frameworks.
