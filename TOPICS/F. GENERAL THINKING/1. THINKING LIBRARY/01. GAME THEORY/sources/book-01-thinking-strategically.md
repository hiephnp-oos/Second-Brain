## PDF ↔ Markdown validation

Validation basis:
- PDF treated as the canonical source representation.
- Markdown treated as the extraction used for search/retrieval.
- Title/author identity matches.
- Major contents hierarchy matches.
- Chapter sequence matches.
- Chapter anchors were found in both representations.
- The extracted Markdown has approximately the same word volume as the PDF text extraction (about 115k words), indicating broad content coverage.
- Source-aware spot checks across strategic moves, credible commitments, prisoners' dilemma, equilibrium, brinkmanship, cooperation, bargaining, and incentives found corresponding passages in both PDF and Markdown.

Known extraction artifacts remain in the Markdown, including malformed heading levels, OCR/formatting artifacts, and flattened tables/diagrams. These are not used as the repository's source of truth. Knowledge entries were distilled against the PDF with the Markdown used as a retrieval aid.

## Acceptance decision

Status: STRUCTURALLY ACCEPTED FOR KNOWLEDGE EXTRACTION

This acceptance means the pair is sufficiently traceable for controlled knowledge distillation. It does not mean the raw Markdown extraction is a clean canonical transcription.

## Distillation boundary

The repository stores:
- distilled concepts;
- reusable mental models;
- source-derived application patterns;
- reusable lessons;
- traceability metadata.

The repository does not store:
- the full book;
- a reconstructed full transcription;
- long verbatim passages;
- a replacement for the private source.
