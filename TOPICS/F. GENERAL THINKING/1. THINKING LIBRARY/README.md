# Thinking Library

## Purpose

The Thinking Library stores durable framework knowledge derived from structurally accepted source material.

It is intentionally layered:

\`\`\`
Source → Concepts → Mental Models → Applications → Reflection → Reusable Lessons → Personal Principles
\`\`\`

## Framework boundary

The initial physical-library candidates are:

1. Game Theory
2. Systems Thinking
3. Bayesian Thinking
4. Critical Thinking
5. Psychology
6. Negotiation

Decision Frameworks and Strategic Thinking are currently cross-cutting synthesis lenses. They can combine knowledge from multiple library domains without requiring their own folders.

## Source boundary

Source PDFs/full extracted books remain outside the public repository when they are copyrighted. The repository keeps source metadata and traceability, then stores only distilled, reusable knowledge.

A source must pass the intake normalization and PDF↔Markdown validation gate before it can become a source for durable knowledge.

## Framework folder contract

When a framework has enough real material to justify its own folder, use:

- \`README.md\` — scope, routing, when to use, and when not to use.
- \`concepts.md\` — distilled foundational concepts.
- \`mental-models.md\` — practical reasoning models/checklists.
- \`applications.md\` — real applications and cases.
- \`lessons.md\` — reusable lessons.
- \`sources/\` — source metadata and traceability, not full copyrighted book text.

Do not create every possible framework folder in advance.

## Materialization rule

Create a framework folder only when durable concepts, reusable mental models, recurring routing demand, or multiple sources/applications justify a stable knowledge boundary.

The library is a knowledge layer, not an archive of books and not a duplicate of domain-specific topic knowledge.
