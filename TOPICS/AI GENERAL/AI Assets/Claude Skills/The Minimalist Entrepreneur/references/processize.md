# Processize

## Purpose

Convert a product idea into a manual, repeatable process that can be executed immediately without building software.

---

## When to Apply

- Have an idea but chưa xây product
- Muốn test bằng manual execution
- Cần hiểu workflow thực tế trước khi code
- Sau bước validate, trước MVP automation

---

## Core Principle

Processize before productize.

Deliver value manually first, then:
- document → systemize → automate

---

## Workflow

### Step 1 — Define Core Function

Clarify:

- What is the one outcome delivered to the customer?
- What changes before vs after using the solution?
- How to deliver this outcome without technology?

Constraint:
- Must be executable manually within short time

---

### Step 2 — Identify Real Users

Ensure real demand:

- Who is currently solving this problem with workarounds?
- Where can they be reached?
- Can you name at least 10 specific individuals?

If not → return to community stage

---

### Step 3 — Design Manual Workflow

Define exact process:

- Input: what customer provides
- Processing: step-by-step actions performed
- Output: what customer receives
- Time: duration per customer

All steps must be concrete and observable

---

### Step 4 — Document Process (Systemization)

Create a full execution document:

- Trigger: what starts the process
- Steps: ordered, explicit actions
- Tools: required for each step
- Time per step
- Output delivery method

Goal:
- Another person can execute without guidance

---

### Step 5 — Validate with Payment

Test real value:

- Set a price (even minimal)
- Deliver to at least 3 real users
- Collect payment and feedback

No payment → no validation

---

### Step 6 — Transition to Productization

Only proceed when:

- Delivered to 10+ paying users
- Workflow is stable and repeatable
- Customer requests are predictable
- Delivery consumes significant time

Then:
- Automate highest-cost step first
- Maintain validated workflow structure

---

## Constraints

- No coding before validation
- No automation before repetition
- No scaling before consistency
- No abstraction before real usage

---

## Output

Define clearly:

1. One-sentence description of manual service
2. Full step-by-step process (systemized workflow)
3. List of 3 real users to test with immediately
4. Initial pricing
5. First candidate step for future automation
