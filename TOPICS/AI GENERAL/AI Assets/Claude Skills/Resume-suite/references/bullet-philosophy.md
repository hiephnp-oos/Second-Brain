\# Bullet Philosophy — Resume Writing Principles



Loaded by M2 as supplementary checklist. Compact version of core framework.



\---



\## Core Meta-Principles



| Principle | Wrong | Right |

|-----------|-------|-------|

| Proof > Claim | "Excellent leadership skills" | "Led cross-functional launch reducing ramp-up 25%" |

| Outcomes > Responsibilities | "Responsible for quality inspection" | "Reduced customer defects by improving inspection flow" |

| Specificity > Generic | "Used software tools" | "Automated reporting using Excel VBA and Power Query" |

| Scanability | Write to be read fully | Recruiter skims in \~7 seconds — impact must hit immediately |

| Impact density | More bullets = more coverage | 1 strong bullet > 5 duty bullets |



\---



\## Bullet Formula



```

\[Outcome verb] + \[context / JD keyword] + by/through + \[method / tool / detail]

```



Example:

```

Reduced production downtime by implementing preventive maintenance scheduling using SAP PM.

```



\*\*Lead word rule:\*\* First 3–5 words must be an outcome verb.

Strong leads: Reduced / Improved / Generated / Led / Delivered / Accelerated / Optimized / Increased / Launched



\---



\## Duty vs Accomplishment



\*\*Duty\*\* (rewrite mandatory):

\- "Managed sales team"

\- "Coordinated with suppliers"

\- "Responsible for production"

\- "Supported QA team"



\*\*Accomplishment\*\* (refine if needed):

\- "Increased sales 20%"

\- "Reduced supplier lead time across 12 vendors"

\- "Improved throughput by..."



Employer already knows what the role does. They need: \*what changed because of you.\*



\---



\## Quantification Quality



Having a number is not enough. Number must carry business meaning.



| Weak | Strong |

|------|--------|

| "Managed 12 suppliers" | "Reduced supplier lead time 20% across 12 vendors" |

| "Taught 30 students" | "Improved student pass rate 15% across 30 students" |

| "Worked on 4 lines" | "Set up 4 production lines for VF8 program, managing USD 226K investment" |



Flag as `\[needs context]` if number has no operational meaning.



\---



\## Skill Embedding



Do not:

```

Skills: Excel, SAP, Python

```



Do:

```

Reduced reporting time by automating KPI tracking using Excel VBA.

```



Benefits: ATS still detects keyword + recruiter sees practical usage + skill has credibility context.



\---



\## Technical Specificity = Credibility



Name tools, systems, methodologies, equipment wherever possible.

\- Vague: "Used ERP system"

\- Specific: "Configured inspection workflows in SAP QM"



Name-dropping (company / customer / product / platform) increases perceived legitimacy — avoid NDA violations.



\---



\## ATS: Acronym Trick



First mention of any important keyword → include both forms:

```

Customer Relationship Management (CRM)

Statistical Process Control (SPC)

```

ATS detects both acronym and full phrase. HR reads full name without confusion.



\---



\## Career Highlights Section



\*\*Preferred over generic Summary.\*\* Acts as "compressed accomplishment section" — hook in 10 seconds.



Structure (5 bullets max):

1\. `\[X]+ years in \[domain(s)]` — use "+" for perception advantage

2\. Professional win 1 — outcome + metric (strongest first)

3\. Professional win 2 — outcome + metric

4\. Key differentiator — cert, rare skill, industry/tool exposure

5\. Humanizing factor (optional) — memorability signal, not generic hobby



Goal: recruiter understands full value proposition in one skim pass. ATS still parses normally.



\*\*Detection rule (used in M1):\*\*

\- CV has generic Summary (claim-heavy, no metrics, no outcomes) → flag for Career Highlights conversion

\- Signal words: "responsible for", "experience in", "focused on", "strong background" without supporting metrics = claim-only → recommend convert

\- CV already has Career Highlights section → skip flag, treat as-is



\---



\## Bullet Prioritization



Strongest bullet first in each role block.

Generic / procedural bullets go last or get pruned.



Priority order within a role:

1\. Achievement with metric (USD, %, time, scale)

2\. Achievement without metric but with clear outcome

3\. High-complexity execution (cross-functional, multi-site, high-investment)

4\. Standard execution

5\. Documentation / support (prune if low-relevance)
