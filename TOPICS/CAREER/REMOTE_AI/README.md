# Remote / AI

## Purpose / Scope

Recurring discovery and evaluation of remote opportunities using the user's engineering, quality/manufacturing, project, documentation, and practical AI capabilities. This includes remote full-time roles and remote contract, part-time, freelance, and AI-enabled work.

## Current Context

This workstream runs in parallel with Job Search and Company Radar. It is not only a fallback: a strong remote opportunity can be relevant regardless of local availability.

Two operating modes should be distinguished:

1. `REMOTE_FULL_TIME` — remote 9–5/full-time opportunities. Prioritize strong matching and compensation; normal full-time availability applies.
2. `REMOTE_SIDE_WORK` — contract, part-time, freelance, project-based, or AI work performed alongside the current 9–5. Use the current reference baseline of approximately `21:00–00:00 ICT`, `2–4 days/week`, around `6–12 hours/week`.

## Working Rules

- Do not use traditional ATS match alone.
- Evaluate the combination of domain expertise, quality/manufacturing experience, project capability, AI leverage, deliverable fit, evidence, remote feasibility, engagement type, compensation, and schedule compatibility.
- Distinguish remote from hybrid, location-restricted, contractor-only, and timezone-restricted work.
- For side work, verify expected weekly hours, synchronous meetings, timezone, response-time expectations, and whether the deliverables can realistically be completed during the available evening window.
- Remote full-time roles may use the normal full-time availability model and should not be penalized for daytime hours merely because side-work mode has an evening constraint.
- Do not inflate AI capability. Treat AI as an additional practical capability built around engineering/quality expertise unless stronger evidence is available.
- Do not fabricate technical-writing, coding, consulting, portfolio, or tool experience that is not evidenced.
- Evaluate contract/freelance work on scope, deliverables, time commitment, compensation, client requirements, repeatability, and payment/risk signals.
- Unknown salary or budget is not automatically a rejection; mark it unknown and assess the remaining evidence.

## Remote / AI Search Categories

Search in parallel across these categories:

1. AI training / evaluation / technical SME roles using engineering, manufacturing, quality, or Vietnamese-language expertise.
2. Technical documentation, SOP, quality-documentation, technical-writing, or process-documentation work.
3. CAD, engineering drawing, DFM, drawing review, and manufacturing documentation.
4. Remote quality work involving ISO/IATF, PPAP, PFMEA, Control Plan, 8D, audit/documentation, or manufacturing-process knowledge where the deliverable can genuinely be completed remotely.
5. Project coordination, PM support, technical operations, documentation, and process-improvement work.
6. AI-assisted engineering, research, data, workflow, automation, and process-improvement work.
7. Remote full-time Quality / SQE / Project Quality / Project Manager / Assistant PM / R&D / Engineering roles when matching and compensation are strong.

The supplied remote-matching reference demonstrates that AI contractor/technical SME, ISO/QMS documentation, automotive quality, CAD, business documentation, operations/project coordination, technical writing, and small project-review tasks can all be considered. The current search should re-evaluate each opportunity against the current profile rather than inherit the earlier ranking.

## Matching Model

Use a separate Remote / AI fit model. A practical baseline is:

- Domain / engineering / quality fit: 25%
- Deliverable / task fit: 20%
- AI leverage or AI-enabled value: 15%
- Evidence / delivery credibility: 15%
- Remote feasibility: 10%
- Compensation / commercial fit: 10%
- Schedule compatibility: 5%

This is a screening framework, not a rigid automatic rejection score. Hard blockers override a high score, and borderline cases should be surfaced for verification.
